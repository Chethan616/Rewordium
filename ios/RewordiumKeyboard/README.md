# RewordiumKeyboard target

Custom Keyboard Extension powered by [KeyboardKit](https://github.com/KeyboardKit/KeyboardKit) (free MIT tier, v10.5.x).

## Files in this folder

| Path | Role |
|---|---|
| `KeyboardViewController.swift` | Subclass of `KeyboardInputViewController`. Sets up the `KeyboardApp` and installs our root SwiftUI view. |
| `Views/RewordiumKeyboardView.swift` | Top-level layout: AIToolbar + KeyboardKit's stock `KeyboardView`. |
| `Views/AIToolbar.swift` | The morphing surface above the keyboard. Collapsed pill ⇄ 8-action grid ⇄ loading ⇄ result preview. |
| `Views/RewordiumMaterial.swift` | Visual tokens (spacing, radius, animation curves) + material modifiers. |
| `Services/SharedSettings.swift` | Read-side of the App Group bridge. Values come from Flutter via `KeyboardSettingsBridge` on the host. |
| `Services/GroqClient.swift` | Bare-metal URLSession Groq client. No Firebase, no Auth — extensions can't carry that weight. |
| `Services/AIService.swift` | `@Observable` façade the SwiftUI views drive. Single-flight semantics. |
| `Models/AIAction.swift` | Enum of the 8 actions + their prompt templates. |
| `Info.plist` | Extension manifest. `RequestsOpenAccess=true`, English as primary language. |
| `RewordiumKeyboard.entitlements` | App Group membership in `group.com.noxquill.rewordium`. |
| `PrivacyInfo.xcprivacy` | Required privacy manifest. |

## Wiring

Pbxproj is generated by `ios/scripts/setup_keyboard_target.rb`. It runs on every Codemagic build (idempotent), and can be run locally on a Mac with:

```sh
gem install xcodeproj           # one-time
cd ios && ruby scripts/setup_keyboard_target.rb
```

## What the keyboard shows

* **Default mode:** small "Tap to rewrite with AI" hint on the left, sparkle "AI" pill on the right. Just above the system QWERTY.
* **Tap AI pill:** the bar morphs into a 2×4 grid of action chips — Rewrite, Shorten, Expand, Professional, Friendly, Fix grammar, Translate, Custom.
* **Tap an action:** bar collapses to a one-line loading state with the action label and a small spinner.
* **Result:** bar shows a preview of the rewrite (up to 3 lines) with "Try again" / "Apply" buttons. Tap Apply → original text is replaced via `textDocumentProxy`.
* **Custom:** swaps the chip grid for a multi-line text field where the user types an arbitrary instruction.

Everything happens inline — no modal sheets, no overlays. The keyboard's vertical extent grows in place with a spring animation so the typing area stays put.

## What's deliberately not in v1

| Feature | Reason |
|---|---|
| Autocomplete suggestions | Pro-only in KeyboardKit. iOS's system text suggestions still apply since we use the standard `textDocumentProxy`. |
| Emoji keyboard | Pro-only. Users can long-press the globe to switch to iOS's emoji keyboard. |
| Themes | Pro-only. Defer until v2; the stock keyboard inherits dark/light from the host app already. |
| Glide / swipe typing | Not in KeyboardKit at all. Would require an ML model + path tracker; out of scope until v3+. |
| Streaming Groq responses | Adds complexity without much UX benefit — Groq replies in <2 s for qwen3-32b at our token budget. |
| iOS 26 Liquid Glass material | The toolbar surface uses `.ultraThinMaterial` today. Wrap it in `if #available(iOS 26, *)` → `.glassEffect()` once we confirm the SDK is in Codemagic CI. |
| Sign-in / Firebase from the extension | Memory ceiling is ~60 MB. The host app writes a short-lived Groq token into the App Group; the extension reads it. |

These are tracked in `KEYBOARDKIT_INTEGRATION.md` (project root).
